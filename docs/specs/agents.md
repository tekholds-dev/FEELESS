# ⚙ The agent kernel — one market state, one candidate lifecycle, one ten-agent brain

Branch `refactor/agent-command-kernel` (2026-10-12). Philosophy: `backend/trench_crew.py` + `docs/TRENCH_CREW.md`.

## The ONE path

```
sources (open board · newest launches · Pump live / pulse / trending / migrations · callouts · movers · volume · new pools · tracked lists)
  → the desk (agents.py: Tally's tape, Sherlock's drivers, Trigger's chart read, Devil's objections) builds ONE row per mint
  → trench_kernel.state.MintStore.ingest   one MintState per mint (deduped), events raised only for what changed
  → trench_kernel.brain.think               ten pure opinions → ONE reducer → status + rank   (only affected mints re-judged)
  → KERNEL.ready()                          the ONE list a seat fill reads (trench mode)
  → Warden (office.warden) → agent_seat → the ONE keeper (fuse_wallet / _fw_execute)
live prices (6-second guard) → KERNEL.price_event → Reaper's opinion now; office.fast_reap acts on the card
```

## MintState (one per mint, each section its own timestamp)

| section | fields | timestamp |
|---|---|---|
| identity | mint · symbol · pair · sources[] · ageH · launch | firstSeen |
| market | price · marketCap · liquidity · volume5m / 1h · pace · buyShare · move5m · liqChange · trades1h | priceAt · marketAt |
| chart | state · phase (market_wake.PHASES) · src · candles · quality · entry | candleAt |
| chain | holderStatus (PENDING / READY) · holderSafe · top10 · rug · earlyWallets · press · cls | holderAt · walletAt |
| research | status (READY / UNKNOWN) · site · x | researchAt |
| objections | Devil's raw objections from the desk | — |

## Candidate lifecycle (one meaning everywhere)

`DISCOVERED → TRACKING → CONTENDING → READY → ORDER_PENDING → HELD → EXIT_PENDING → CLOSED`

- TRACKING = data pending, outside the universe, or the hard wall — **never "rejected"**.
- CONTENDING = passes the wall, ranked.
- READY = Trigger ENTER + no hard veto + execution healthy + rank ≥ 120.
- Held positions are HELD / EXIT_PENDING whatever their cap (a winner over $200K is never sold for crossing the entry cap).
- Cooldown is metadata on the candidate, not a second universe.

## The ten agents (pure — they never fetch)

Tally measures · Sherlock lists known / UNKNOWN and *requests* evidence · Weather ×0.8…×1.1 · Trigger reads the live narrative (ENTER / ARM /
WAIT / NO) · Devil grades INFO / WARNING / STRONG_WARNING / HARD_VETO (only the wall is HARD) · Warden sizes (≥ ×0.5, ×0 only on a hard
veto) · Courier = execution health · Reaper = HOLD / PROTECT / TAKE / EXIT for held coins · Archivist = sources · Judge = evidence weight.

Rank = `opportunity.open_score` (newness × volume velocity × buyer velocity × momentum × early wallets × Judge × Devil confidence) × Weather × Sherlock.

## Four hunter lanes

HUNTING (searching; shows the best contender) · ARMED (a READY coin lined up) · HELD (capital in). The office never sleeps because seats are cash.

## Enrichment tiers (one scheduler: `_kernel_pass`)

- Tier 0: every discovered coin — board numbers only, **zero Solana RPC** (tested).
- Tier 1: real 1-minute candles for the fresh / strongest (`office_edge.candle_order`, the candles service).
- Tier 2: holder / early-wallet scans for the `ENRICH_TOP` 4 best-ranked candidates Sherlock asks about → `_runner_intel` (one scan per mint in flight).
- Tier 3: public research (`social_research`) on the strongest.

## RPC

`chain_rpc._rpc` = singleflight over `_rpc_physical`: identical in-flight reads share one request (writes never coalesced). `RPC_STATS`
(logical · physical · saved · 429 · refused) is in the payload. `RPC_SCAN_RPS` default stays **1.0** (the deliberate 2026-10-08 value; 0.3 / 0.5
starved the scan queue). Keyed lanes, quota parking, per-method refusal, keeper priority, public fallback and re-broadcast are unchanged.

## UI

`frontend/src/lib/agentHub.js` — `useAgentHub()` is the one store (snapshot + shared live prices) with selectors; `KernelBoard` (SeatOps) shows the
lanes and candidates; `agentRead.rowState` is the one decision meaning (a Devil warning is ⚠, only a hard veto is ✕ BLOCKED).

THE COCKPIT (`components/command/AgentCockpit.jsx` + `lib/cockpit.js` + `styles/agentCockpit.css`, the top of HQ › Agents, built to the owner's
reference): mission ribbon (`missionTiles`: put in · equity · net P&L · phase · breakeven · lives · occupancy · cycle · last real action · cash ·
keeper · execution) → four seats (`seatCards` + `seatState`: HUNTING · ARMED · HELD · PROTECT · ROTATE · EXITING · OPEN) → ONE market-cap chart
(price × the kernel's resolved supply; unknown supply = MC UNAVAILABLE, never a price chart) with the tape's real events lettered T D W B R X
(`letterMarkers`) → the LIVE DECISIONS strip (the kernel's decision tape) | the AGENT DECISION PANEL (live decision · inputs with freshness words ·
seats · owner review · trace in chain order) → the ten-agent matrix | review queue + OWNER REVIEW → operator controls (the creator's own limits on
the same `/admin/agents {cfg}` path) + the AI chip. Everything older (KPI tiles, lenses, the office room) sits in ONE `▸ MORE` fold. An agent pulses
only when ITS tape id moves (`newEvents`); MC / % / $ glide to each real value at ≤ 30fps (`useEasedNumber` — display only, no request).

## AI router (advisory; a PROVEN stance may weigh ±10% on the rank)

`backend/ai_router.py` (`ROUTER.reason(http, env, cfg, case, role)`): OpenAI-compatible chat providers tried in order — local LM Studio
(`LOCAL_LLM_ENABLED` / `LOCAL_LLM_BASE_URL` loopback only / `LOCAL_LLM_MODEL`, ONE inference at a time + a queue of 2) → Groq → OpenRouter → OpenAI →
xAI → any OpenAI-compatible host. Timeout / 429 / refused / malformed = the next provider; all fail = `NONE` (deterministic only). Answers are a
validated JSON object (`parse_advice`: stance from a fixed list, numbers clamped, summary ≤ 200 chars) cached per case state and shared while in
flight. Roles that may ask: Sherlock · Devil · Judge · owner review · manager. NEVER: Tally, Trigger, Reaper, Courier, Warden (refused in code).
The service's `_ai_loop` (own task, every 15s, ≤ 3 cases: owner review → a conflicted ENTER + Devil warning → the top contender → the newest Judge
review) writes `office.ai.notes[mint][role]` + the decision log `office.ai.log` (🧠 AI tab). LOW USAGE: `case_key` = the case's STATE (status ·
trigger · Devil's objections · coarse numbers), cached 10 min — a coin that only wiggled is not asked again. Sherlock's brief (`_ai_brief`: holders ·
chart · flow · launch · crowd, one short line each) is built from readings the desk already has — no fetch. THE AGENTS LEARN FROM THE MODEL ON ITS
RECORD (`backend/ai_learn.py`, `data/ai_proof.json`): each stance is noted at that price, judged 15 min later (no price for 1h = −100%); a stance moves
the kernel's rank (`opportunity.open_score(ai_w=)`, ctx `aiw`) by ×0.9 / ×1.1 only with ≥ 20 judged calls AND a typical result clearly better / worse
than the model's other calls. Unproven = ×1.0. The model never places, sizes, blocks or sells. `POST /admin/ai/ask` = the owner asks about one coin. Owner routes: `GET|POST /admin/ai/providers` (order + on / off,
`data/ai_providers.json`, no secrets) · `POST /admin/ai/test` · `POST /admin/ai-key` (keys tested, saved to backend/.env, never returned).

## Legacy kept on purpose

- `agents.py` desk (desk / investigate / manage / evolve / survival / lives / burn) — it still builds the rows the kernel reads, runs the four
  desks' learning and real-money survival, and manages positions when trench mode is off. Its GO is an input, not the decision.
- `fill_plan` (GO / cleared cases / round-3 ENTERs) — the non-trench path when `agentOpen` is off.
- `arena_prime.py` / Prime cards — other products; they do not reach the kernel.

## 3 · 🤝 The duet — how the two grow together (`backend/ai_duet.py`)

1. Gemma reads the best unread READY / CONTENDING coin (the local lane).
2. If Gemma made a real call (CAUTION / FAVOR), Qwen re-reads the same case (≤ once / 150 s, never while a browser lags).
3. Both reads are graded on their own (15 min later, real price) **and** as a PAIR: agree %, how agreed calls did, who was right

4. A split stays NEUTRAL until one model has won ≥ 10 called splits at ≥ 60% — then splits go its way. The pair learns whose voice

5. An AGREED CAUTION may hold a coin back from a real seat (a lone small model never could). It can only make the agents buy LESS.
6. Chat: Brain › model switch › 🤝 Duet — Gemma answers, Qwen reads Gemma's answer and agrees or pushes back; both are shown.

Shown on HQ › Agents › 🧠 AI: the MODEL REPORT CARD (every model on one yardstick) + the DUET meters.

# 💵 Real-money cats — the full user process (design, NOT built)

> Planning status and remaining requests: [HANDOFF.md](HANDOFF.md) `## TASKS`. This file retains the technical specification/history; do not maintain a second active backlog here.

Owner ask (2026-10-21): "Build a Cat needs to show the models, the whole shabang — no paper, real money, and creator-wallet access in HQ
for how much I charge per …". Every step below must exist before any of it ships (one and done). Today every cat is PAPER.

## The decision that blocks everything (owner)
Who holds a real cat's money?
- **A. The user's own wallet signs each trade** — non-custodial, legal-light, but the cat is not autonomous: every buy / sell is a wallet
  prompt (FEELESS can pre-build and alert, like Fuse one-tap cards).
- **B. A per-user wallet FEELESS controls (Circle / keeper)** — autonomous, but FEELESS holds user funds = custody (licensing, security,
  audits). Breaks the standing rule "never hold user keys".
- **C. An on-chain cat program (like the FUSE Card program)** — the cat's funds sit in a program account only the user can withdraw; a keeper
  may only trade inside the user's signed limits. Autonomous AND non-custodial, but needs the program, an audit and a devnet run first.

## The process (whichever option)
1. **Pick brains** — the whole OpenRouter list (`/api/cats/models`): price per decision, memory, intelligence, categories; up to 2 brains + how
   they work together (turns · discuss · together · battle).
2. **Identity** — name, handle, coat, look (same fields as Create a Cat — `CatFields`).
3. **Risk** — balance, max position, daily buy limit, daily loss limit, the one-time brief.
4. **Pricing shown before funding** — the creator's fee (HQ › Fees › Cats: $ per decision markup, % of profit, flat launch fee), the model
   cost per decision, network fees. Example $ for this setup.
5. **Fund** — the user's signed SOL transfer (A: none, B: to their cat wallet, C: into the program account).
6. **Live** — decisions on the wall, every trade with its tx, P&L price-only, fees apart, the brain's words.
7. **Controls** — pause, chime in (advice), pull all funds (sell everything → back to the user's wallet), top up, change limits.
8. **Billing** — model + creator fees settled from profit or pay-as-you-go, every charge on a receipt; nothing charged on a losing day
   beyond the model's real cost (owner decides).
9. **Exit** — withdraw anytime to the user's own wallet; receipts + record stay on the profile.
10. **HQ** — creator sees every live cat, revenue per cat, fee settings, kill switch per cat, the audit trail.

## What must be proven first

# 🪖 The Trench Crew — trenching only

The agents are a **trench crew**, not a compliance committee. They keep digging until they understand what is happening, then
**Warden** and **Courier** enforce only the few things that can actually blow up execution.

> **Tally discovers. Sherlock investigates. Weather contextualizes. Trigger times. Devil challenges.
> Warden sizes. Courier executes. Reaper manages. Archivist remembers. Judge improves.**

Code: `backend/trench_crew.py` (roles, the hard wall, Devil's weights, Warden's shrink rule) · ranking `opportunity.open_score` ·
the wall `opportunity.open_ok` · live narrative `opportunity.narrative` · switch: real card `agentOpen` (HQ › Agents › ⚙ Control).
Change this file and `trench_crew.py` together — `tests/test_trench_crew.py` checks they agree.

## The crew

| Agent | Role | What it does | What it never does |
|---|---|---|---|
| 📊 Tally | MARKET TRUTH / DISCOVERY | Sees every fresh coin first (Pump, Pulse, Radar, RPC, migrations, volume leaders, movers, new pools) and measures it: newness, cap, price, liquidity, volume velocity, buyer velocity, trades, acceleration, candle / tape freshness, source. | Decide good or bad. A weird coin stays visible unless its data is unusable. |
| 🔍 Sherlock | DEEP INVESTIGATOR | The most curious bot in the office. Chases public clues: deployer / funders, first buyers, wallet clusters, bundles, early-wallet behaviour, site / X, narrative, copycats, prior launches of related wallets, whales accumulating or distributing — does the story match the chain? | Say "no verification = reject". Missing proof is **UNKNOWN / UNPROVEN** — a research state. |
| 🌦 Weather | MARKET CONTEXT | Reads the whole trench: is Pump hot or dead, do launches follow through, are buyers chasing everything, do rugs dominate, do leaders hold gains? | Shut the office. It changes how aggressively the desk sizes (never below ×0.5 in trench mode). |
| ⏱ Trigger | ENTRY TIMING | Decides **when**, from the live FEELESS chart / tape: early acceleration, first pullback, reclaim, breakout, momentum resumption. Reads a newborn chart as a newborn. | Demand a textbook setup or a long history. |
| ⚖ Devil | ADVERSARIAL THINKER | Asks "what could make us wrong?" and weighs each objection by severity. | Kill the trade. Objections are confidence deductions (strong ×0.85, others ×0.95, never below ×0.6). Only the hard wall is a no. |
| 🛡 Warden | RISK TRANSLATOR | Answers "how much can we risk here?" — strong but uncertain = smaller; excellent = the creator's cap. | Invent reasons to say no. Uncertainty rules only **shrink** (≥ ×0.5); only execution health and a seat too small for its own costs stop a buy. |
| 📮 Courier | EXECUTION TRUTH | Mechanically strict: route, price, slippage, fill, signature, duplicate-order protection, can it be bought **and** sold — through the one existing keeper path. | Have an opinion on narrative. |
| ☠ Reaper | POSITION MANAGER | Watches the **live** chart every 6 seconds: P/L velocity, peak, support, structure, liquidity, early-wallet exits, challengers. Lets accelerating runners run, protects when momentum stalls, exits when the thesis breaks. | Dump a winner because a clock expired, or babysit a dead loser. |
| 🗄 Archivist | MEMORY / EVIDENCE | Remembers what really happened: every round, source, entry reason, clue, P/L path, MFE / MAE, exit, outcome — wins and losses. | Turn a pattern into an instant hard restriction. |
| 👨‍⚖️ Judge | ACCOUNTABILITY / EVOLUTION | After a loss: bad selection, timing, size, hold, exit, execution, or normal variance? After a win: what worked? Adjusts **weights** through repeated evidence; a desk that keeps losing real money starts its next generation. | Add a hard veto after a bad trade. |

## The ranking

`open_score` = **newness × volume velocity × buyer velocity × live momentum × early wallets × the Judge's evidence weight × Devil's confidence**.
No holder, rug, creator, coin or source reputation part. No advantage for old history.

Newness: 0–5m ×1.5 · 5–15m ×1.35 · 15–60m ×1.2 · 1–3h ×1.0 · 3–6h ×0.8 · older = outside the universe.

## The live narrative

Built from THIS pass only: **HOT EARLY MOVE · BUILDING · BREAKOUT · RUNNING · STALLING · DISTRIBUTING · COLLAPSING**.
DISTRIBUTING and COLLAPSING are skipped at once; the desk moves to the next coin.

## The HARD WALL (the money boundary — the only things that can stop a trench buy)

- no live price · no trades in the last 5 minutes
- outside the universe: live cap inside the owner's MC band (default $12K–$300K, HQ › Agents › controls) and ≤ 6h old
- a pool the keeper cannot buy into
- market data invalid / malformed / a bot ladder
- the live chart collapsing or distributing · the dev dumping now
- no route back to SOL / a sell-back tax · a price far from market (the keeper's own checks)
- keeper halted · Courier reads BAD · office not live
- a seat too small for its own round-trip cost → reported as **SIZE TOO SMALL FOR COSTS**, not as a strategy failure

Everything else is curious, adaptive and evidence-weighted.
